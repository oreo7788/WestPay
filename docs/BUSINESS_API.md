# 外部业务系统订单接口

业务系统推送订单后，本平台在同一事务内保存订单、预留手续费、生成并保存独立收款二维码。成功响应直接带回收款链接、二维码地址及支付状态。

## 准备

1. 按 [微信 JSAPI 配置说明](WECHAT_JSAPI.md) 配置并启用微信支付。
2. 后台新增商户，准备足够的预付手续费余额。
3. 通道管理中新建已启用的“微信支付 / 微信 JSAPI”通道，配置费率和金额范围。
4. 管理员进入“商户列表 → 接口接入”，生成该商户的 API 密钥。密钥只展示一次，数据库只保存其哈希；重新生成或撤销会使旧密钥失效。
5. 将 `/api/v1/*` 由已有 HTTPS 入口转发至本机服务。外部业务系统只在自己的后端保存和使用密钥。

以下例子使用 `https://pay.example.com` 作为示例域名，密钥均为占位内容。接口不使用管理后台的登录 Cookie。这是本平台签发的接单密钥，与微信商户私钥或 API v3 密钥不同。

请求头：

```http
Authorization: Bearer west_REPLACE_WITH_YOUR_MERCHANT_API_KEY
Content-Type: application/json
```

商户身份由 API 密钥确定。请求体不能指定其他 `merchantId`；密钥只能访问所属商户的订单。商户停用后密钥无法继续调用接口。

## 创建订单

`POST /api/v1/orders`

```json
{
  "merchantOrder": "SHOP-20261015-0001",
  "amount": 19.90,
  "description": "商品订单付款"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `merchantOrder` | 是 | 同一商户下唯一，去除首尾空白后 1–100 字节；用它进行重试去重 |
| `amount` | 是 | 人民币元，JSON 数字，大于零且最多两位小数；内部转为整数分 |
| `description` | 否 | 商品描述，最多 127 字节；省略时使用产品名称，并在创建时保存快照 |
| `productCode` | 否 | 默认 `PAY-WX`；必须为启用且与通道匹配的微信支付产品 |
| `channelId` | 否 | 指定已启用的微信 JSAPI 通道；省略时按金额限额筛选，再按通道费率及 ID 选择，不回退到模拟通道 |

新建成功返回 `201`。同一商户订单号的相同请求重试返回 `200`，并复用原订单、收款地址和二维码，不重新扣预留手续费。原订单已支付或已过期也仍返回原订单；创建新交易必须使用新的商户订单号。若相同单号对应的金额、产品、明确指定的通道或描述不同，返回 `409`。

响应示意（仅列主要字段，实际响应还包含商户、产品、通道等信息）：

```json
{
  "systemId": "P-example",
  "merchantOrder": "SHOP-20261015-0001",
  "description": "商品订单付款",
  "amount": 19.9,
  "status": "未支付",
  "payUrl": "https://pay.example.com/pay/ORDER_CHECKOUT_TOKEN",
  "qrImageUrl": "https://pay.example.com/api/cashier/ORDER_CHECKOUT_TOKEN/qr.png",
  "qrImage": "/api/payments/P-example/qrcode",
  "expiresAt": 1792035000,
  "canPay": true,
  "providerOrder": "WXexample",
  "providerTxn": "",
  "callbackAt": ""
}
```

- `payUrl`：展示给付款人的收款网页链接。
- `qrImageUrl`：可直接用于展示给付款人的 PNG 二维码地址，无需附带商户 API 密钥。二维码内容为 `payUrl`。
- `qrImage`：仅供已登录管理后台查看的相对地址，支持查看历史二维码；外部系统使用上面的 `qrImageUrl`。
- `expiresAt`：本订单支付截止时间，Unix 秒。二维码不通过重复推送自动延期；已有二维码不随配置改写，在未结订单存在时保留原 HTTPS 域名。
- `canPay`：本地状态和支付期限是否允许继续付款；为 `false` 时不要展示为可支付订单。
- `providerOrder`：发给微信的商户订单号；与业务系统的 `merchantOrder` 分开保存。
- `providerTxn`：后端确认支付成功后的微信支付交易流水。
- `callbackAt`：已确认的支付成功时间，本机时区格式 `YYYY-MM-DD HH:mm:ss`；为空表示尚未确认成功。

## 查询状态

### 读取已保存状态

`GET /api/v1/orders/{merchantOrder}`

将商户订单号进行 URL 编码。使用同一个商户 API 密钥，返回与创建接口相同的订单对象。此接口读取本地状态，不在每次轮询时访问微信。

业务系统可以每 5 秒读取一次，直到取得“已支付”“已关闭”或“支付失败”。“未支付”以及到期但仍在等待微信确认的订单不能当作支付成功。

### 主动向微信查单

`POST /api/v1/orders/{merchantOrder}/query`

请求头仍需商户密钥，无需请求体。后端查询微信并在确认后更新本地状态，返回最新订单对象。已确认支付的终态直接返回已有结果。

网络超时、微信接口异常等情况返回错误，不会直接把订单标为失败或释放尚未确认的预留手续费。可稍后读本地状态或再次查单。

## 支付及列表查看

1. 业务系统调用下单接口并拿到 `qrImageUrl`，展示给付款人。
2. 付款人用微信扫描二维码，打开已绑定金额、商品描述和订单的收款页。授权后调起 JSAPI 支付，金额及 OpenID 由后端校验。
3. 微信成功通知通过验签、解密和订单核对后更新状态；通知延迟时也可通过查单及后台补单确认。
4. 管理后台“收款订单 / 历史订单”增加“收款二维码”列，点击预览可直接扫码，并查看金额、单号、有效期、支付状态。
5. 订单列表默认每 5 秒刷新本地状态，可暂停；二维码弹窗也每 5 秒刷新，并提供“向微信查单”。

查看二维码不会创建新订单，也不会再次预留手续费。支付成功或超时后，后台保留原二维码供核对，并提示不能继续付款；公开收款链接在订单到期 15 分钟后失效。

当前未向外部业务系统推送商户支付回调，业务系统通过上述查询接口获取状态；微信向本平台的支付通知已经接入。

## 常见响应

| 状态码 | 含义 |
| --- | --- |
| `200` | 查询成功，或原订单的相同请求重试 |
| `201` | 新订单及二维码已保存 |
| `400` | 参数、产品、支付方式、限额或通道不符合要求 |
| `401` | 商户密钥缺失、无效、已撤销，或商户已停用 |
| `403` | 商户被黑名单拦截，或管理操作权限不足 |
| `404` | 当前商户下没有该订单 |
| `409` | 相同单号内容冲突，或预付余额不足等状态冲突 |
| `502` | 微信接口请求未完成，需要后续查单确认 |
| `503` | 微信支付未启用或未配置 |

错误响应格式：

```json
{"error":"具体错误说明"}
```

接口密钥和收款链接均不要写入公开日志。当前仅完成本地前后端构建，尚未与真实业务系统和微信商户完成联调；本地服务仍保持停止。
