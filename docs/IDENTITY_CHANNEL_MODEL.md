# 内部与商户：身份及通道开通方案

更新：2026-10-19。本文记录最新确认的产品方案，替代此前的“内部、商户、供应商三方登录”设想。账号、角色权限与商户数据隔离已写入代码；供应商目录、商户通道开通和资金流程尚未完成改造，详见 ACCESS_CONTROL.md。

## 已确认的范围

系统只有两类业务身份：**内部人员、商户**。

所有用户由内部的超级管理员创建并分配角色；商户账号绑定对应商户主体，不提供商户自助注册或自行创建用户的入口。

通道供应商是内部维护的“支持接入目录”，不提供供应商登录入口、供应商工作台或供应商专属收益后台。

| 身份 | 主要职责 |
| --- | --- |
| 内部 | 维护支持的供应商目录及接入要求，管理商户，审核商户提交的通道资料并指定直收/代收模式，控制通道启用状态，处理授权范围内的业务 |
| 商户 | 查看支持的供应商，选择供应商并填写自己的资料，提交审核，查看审核意见，管理自己的已开通通道、订单和账务 |

内部与商户用户均按角色授予菜单、页面及操作按钮权限，由超管统一管理；这属于授权细分，不新增业务身份。具体设计见 [ACCESS_CONTROL.md](ACCESS_CONTROL.md)。

## 商户通道开通流程

```text
内部维护支持列表及资料要求
          ↓
商户选择供应商，填写自身账号及接入资料
          ↓
商户提交审核
          ↓
内部审核并指定直收/代收模式：驳回并说明原因 / 审核通过后启用
          ↓
商户使用自己的已启用通道处理订单
```

审核要求已经确认：**商户不能绕过内部审核直接启用新配置。**

收款模式由内部审核时指定，只能选择供应商支持的模式；商户可查看审核结果和已启用模式，不能自行设置或修改生效模式。审核记录保存指定模式，订单使用已审核版本的模式快照。

本地阶段的审核与启用表示平台内的配置状态。供应商的真实开户、产品权限、凭据有效性及接口连通性在后续外部对接时确认；不能将保存资料或本地审核直接显示为第三方已认证。

## 通道支持两种收款模式

用户已确认两种模式都需要：

| 模式 | 资金实际去向 | 对本地模型的要求 |
| --- | --- | --- |
| 商户直收 | 商户自己的供应商或支付账户 | 订单保留商户通道、收款模式和资金来源；渠道收款统计与平台代收款分别记录 |
| 平台代收 | 平台统一账户，再结算给商户 | 按已确认的结算要求管理待结算、结算确认和可用资金 |

原有“统一资金余额”的要求保留，但需要区分资金来源。不能把已进入商户自己账户的直收款，再自动记成平台持有的可提现款。直收模式的平台服务费如何收取、渠道余额是否纳入总览及提现来源，仍需细化。

## 建议的最小本地数据结构

账号及权限结构已在本轮实现；以下其余数据结构仍为实施建议，尚未全部落地：

1. **账号及权限**：内部/商户身份；商户账号绑定商户主体；超管创建用户并分配角色，角色控制菜单、页面及操作权限，服务端校验数据归属。
2. **供应商目录**：名称、说明、支持的支付方式和收款模式、适配器标识、所需填写的配置项、是否允许新增接入。由内部维护。
3. **商户通道实例**：归属商户、供应商、显示名称、收款模式、商户配置、审核状态、审核意见、审核人和时间、启停状态。
4. **配置版本与审核记录**：提交、驳回、重新提交和审批记录；审核针对具体配置版本。
5. **订单关联**：绑定实际使用的商户通道实例及配置版本，保留支付方式和收款模式快照。

供应商目录属于共享接入能力；商户通道实例属于某一商户的实际配置。同一供应商下，不同商户的资料和订单必须隔离。

当前账号已支持商户身份及主体归属，但 `channels` 仍是全局通道，微信适配器仍读取全局环境配置。这些都需要按商户通道实例改造，不能把全局通道列表直接当作商户各自已开通的通道。

## 配置及权限原则

- 商户只能读取、提交和操作自己的配置与订单；服务端必须校验归属，不能只隐藏菜单。
- 内部维护供应商支持范围和配置项要求；商户按对应要求填写自身资料。
- 密钥等敏感字段保存后显示“已配置”或脱敏状态，不放入列表、导出和操作日志；保存时应受保护。
- 已审核版本与待审核修改分开，未审核修改不能直接替换收款所用配置。历史订单继续关联原版本。
- 平台代收时，建议由内部维护平台共有的私密收款凭据；商户填写自身业务资料，避免向商户暴露其他商户或平台共用凭据。具体字段归属按供应商模板细化。

## 仍需细化，但不影响身份方向的问题

- 每个供应商的必填资料和校验规则。
- 已启用配置变更后的审核与切换方式，以及供应商下架对已有通道的影响。
- 直收和代收的费率、手续费收取时点、待结算口径及提现资金来源。
- 提现/付款审批人员及冻结时点。

## 本地开发顺序

1. 内部与商户账号、商户主体绑定、菜单及服务端数据隔离。
2. 内部供应商目录和商户配置表单。
3. 提交、驳回、重新提交、审核通过启用的流程及日志。
4. 本地模拟收银台及二维码，订单绑定商户通道和收款模式。
5. 按确认后的资金规则完善结算、提现和付款审批。

外部上游和真实支付接口继续后置。账号权限改造已实现并构建，通道及资金流程仍按本方案继续开发；没有启动服务或修改运行数据。
